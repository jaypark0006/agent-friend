# 摄像头色块（1.1.17，源码交付）

2026-10-04：网页新增 `#camera` 页面。用户点击开始后，设备本地取左侧摄像头 UYVY 帧，居中裁成正方形，生成256×256色块，再最近邻放大到480×480图片页。每个色块以中心位置的颜色填充，默认8×8像素，可调1–64。无需把原始帧送到PC后压成JPEG回传，也不在本地先编码JPEG再解码。

目标默认30FPS，可调1–30；不是已经测得或保证的帧率。页面区分摄像头采集、色块生成和LCD实际完成帧率；LCD计数在DMA完成后更新。模块官方规格提供30FPS采集能力，实际整条管线仍由用户后续体验确认：[摄像头模块指南](https://docs.espressif.com/projects/esp-dev-kits/zh_CN/latest/esp32s31/esp-mosaico/user_guide_camera.html)。保留已有摄像头默认格式、尺寸、单缓冲配置和模块识别，不驱动未知板。

开始/应用：开启采集并请求图片页，即使自动切换关闭也会执行这个明确操作。运行时图片页的最新实时源为摄像头；文字页、设置页及图片历史仍可手动浏览。外部JPEG继续被接收和保留，停止后图片页恢复JPEG/历史来源；没有已有图片时保留最后画面。色块帧不逐帧加入图片历史、不会创建虚假的图片未读项；文字未读提示和重力旋转继续适用。

停止时，仅当本功能开启了摄像头且没有其他camera控制请求接管时才关闭采集。此前手动开启的摄像头保持原控制状态。离开网页或关闭浏览器只停止浏览器预览/订阅，设备本地运行继续；本地运行开关与参数仅RAM，重启默认关闭。重新开始可重试失败采集，停止保留所选目标帧率和色块大小。

REST：

| 接口 | 内容 |
| --- | --- |
| `GET /api/camera/render` | 本地运行状态、参数、生成/呈现计数、实际帧率、处理耗时 |
| `POST /api/camera/render` | `enabled`必填布尔；可选整数`target_fps:1..30`、`block_size:1..64`，成功202；参数错误400、worker不可用503、缓冲分配失败500 |
| `GET /api/camera/render/frame` | 最近的256×256 RGB565大端帧，131072字节，500ms内有效，否则503；格式和帧号在响应头 |
| `GET /api/camera` | 原有摄像头状态新增`render`对象 |
| `GET /api/sensors`、`ws://IP:81/ws/sensors` | 同样包含`camera.render`，统一WS仍为10Hz全部状态 |
| `GET /api/status` | 新增`camera_render_enabled`、`camera_display_fps`，原JPEG接收/呈现计数不混入本地画面 |

开始请求例：

```json
{"enabled":true,"target_fps":30,"block_size":8}
```

网页可选低频预览默认关闭：启用后下载已处理色块帧，在Canvas中展开RGB565，最多约5次/秒，不承担设备30FPS显示管线。原始UYVY/WAV入口与REST图片和WS图片协议保持兼容。

实现资源：首次启用申请3个256×256 RGB565槽和1个预览缓存，总计512KiB PSRAM，存活至重启；预览响应额外临时128KiB。摄像头任务保有借用帧，处理完归还；转换和缩放不占用状态锁，槽按FREE/WRITING/READY/READING转移，最新帧替换过时待显示帧。显示任务使用原有备用LCD缓冲与DMA等待路径，不由摄像头任务直接操作LVGL/LCD。

本轮没有编译、启动、刷机、测试、性能基准或实机/浏览器验证。设备仍安装1.1.16；1.1.17须后续按用户授权编译/安装，30FPS未测得。
