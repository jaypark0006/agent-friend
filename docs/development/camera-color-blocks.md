# 摄像头色块（设备第三页，1.1.24）

2026-10-04：网页新增 `#camera` 页面。设备左右滑入摄像头第三页自动开始采集，设备本地取左侧摄像头 UYVY 帧，居中裁成正方形，生成256×256色块，再最近邻放大到480×480摄像头页。1.1.19默认每2×2共4个处理像素合为一个色块，RGB各通道取平均；其他大小保留中心取样填充，可调1–64。无需把原始帧送到PC后压成JPEG回传，也不在本地先编码JPEG再解码。

目标默认30FPS，可调1–30；不是已经测得或保证的帧率。页面区分摄像头采集、色块生成和LCD实际完成帧率；LCD计数在DMA完成后更新。模块官方规格提供30FPS采集能力，本轮SC101IOT默认1280×720 UYVY单缓冲模式报告15FPS，实际采集/色块生成/LCD呈现约7.8FPS，未达到30FPS。参考：[摄像头模块指南](https://docs.espressif.com/projects/esp-dev-kits/zh_CN/latest/esp32s31/esp-mosaico/user_guide_camera.html)。保留已有摄像头默认格式、尺寸、单缓冲配置和模块识别，不驱动未知板。

设备图片/文字/摄像头是三个并列主页面，向左依次循环、向右反向。进入摄像头页自动采集，离开到图片、文字或设置时请求停止；设置底部上滑返回摄像头时重新开启。外部JPEG与文字仍后台保留，自动切换开启时新推送可切到对应页面并关闭摄像头。色块帧不写图片历史，不创建图片未读项，保留重力旋转。

网页#camera只预览和提供参数/设备切页控制；网页进入/离开不再开启/关闭设备摄像头。关闭浏览器也不会影响设备第三页。1.1.18此前浏览器生命周期检查是历史测试，不代表1.1.20设备页已实测。见[设备第三页交付](2026-10-04-native-camera-page-1.1.20.md)。

REST：

| 接口 | 内容 |
| --- | --- |
| `GET /api/camera/render` | 本地运行状态、参数、生成/呈现计数、实际帧率、处理耗时 |
| `POST /api/camera/render` | `enabled`必填布尔；可选整数`target_fps:1..30`、`block_size:1..64`，成功202表示参数/设备切页请求已接受；参数错误400，硬件/缓冲错误异步看render.state/error |
| `GET /api/camera/render/frame` | 最近的256×256 RGB565大端帧，131072字节，500ms内有效，否则503；格式和帧号在响应头 |
| `GET /api/camera` | 原有摄像头状态新增`render`对象 |
| `GET /api/sensors`、`ws://IP:81/ws/sensors` | 同样包含`camera.render`，统一WS仍为10Hz全部状态 |
| `GET /api/status` | 新增`camera_render_enabled`、`camera_display_fps`，原JPEG接收/呈现计数不混入本地画面 |

开始请求例：

```json
{"enabled":true,"target_fps":30,"block_size":2}
```

网页低频预览进入时默认开启，可取消：启用后下载已处理色块帧，在Canvas中展开RGB565，最多约5次/秒，不承担设备30FPS显示管线。原始UYVY/WAV入口与REST图片和WS图片协议保持兼容。

实现资源：首次启用申请3个256×256 RGB565槽和1个预览缓存，总计512KiB PSRAM，存活至重启；预览响应复用主HTTP服务既有256KiB接收缓冲复制128KiB稳定帧，不额外申请内存；这一修改修复实机“No preview buffer”500。摄像头任务保有借用帧，处理完归还；转换和缩放不占用状态锁，槽按FREE/WRITING/READY/READING转移，最新帧替换过时待显示帧。显示任务使用原有备用LCD缓冲与DMA等待路径，不由摄像头任务直接操作LVGL/LCD。

初次1.1.17源码交付没有测试，随后已编译安装。用户本轮明确授权功能测试，最新1.1.18已再次编译安装并实测图片、文字及摄像头流程。见[功能测试与安装证据](2026-10-04-functional-pages.md)。
