# 固件更新记录：根除死机、老重启与长时间静置黑屏假死 (1.1.44)

- 日期：2026-10-25
- 版本：LAN Screen 1.1.44
- 目标架构：ESP-Mosaico (`esp32s31`)
- 固件状态：官方编译通过，`lan_screen.bin` (5,046,832 字节)，通过官方 `app-update` 刷入实机。

---

## 1. 用户反馈与问题现象

用户在实测 1.1.43 固件后反馈以下高危痛点：
1. **“怎么老重启呀？现在”**（系统高频崩溃重启）；
2. **“而且我感觉总是死机 比如我转各种方向的时候”**（旋转朝向或翻转设备时冻屏假死）；
3. **“还有左右滑动的时候”**（在主页左右滑动切页时触发崩溃或假死）；
4. **“还有放的时间长了 就死机了 不响应了”**（长时间放在桌上后完全黑屏无响应，触控不灵）。

---

## 2. 根因剖析与定位

### 根因 1：Pipeline 任务列表每 250ms 疯狂析构重建与悬空指针崩溃 (`screen_widget.c`)
- **致命缺陷**：
  在 `screen_ui_widget_refresh` 中：
  ```c
  if (w->count == 0) {
      lv_obj_clean(a->widget_list_box);
      lv_obj_t *empty_card = lv_obj_create(a->widget_list_box);
      ...
  } else {
      if (lv_obj_get_child_count(a->widget_list_box) == 1) {
          lv_obj_clean(a->widget_list_box);
      }
      ...
  }
  ```
- **后果**：
  1. 当任务列表为空（`w->count == 0`）时，每次周期刷新（每 250ms 一次，每分钟 240 次！）都会调用 `lv_obj_clean` 清空列表容器，并重新 `malloc` 创建 `empty_card` 和多个 label！
  2. 当列表中恰好有 1 个任务（`w->count == 1`）时，`child_count == 1` 判定为真，系统竟误将其当作空卡片而强行 `lv_obj_clean` 销毁，然后重新创建！
  3. 如果用户正在触摸屏幕、左右滑动切页，或者正好在点击 `[L] 批准` / `[R] 取消` 胶囊，被按下的卡片对象瞬间被 `lv_obj_clean` 释放！LVGL 的 `indev->pointer.act_obj` 变成悬空野指针，在下一次事件循环时解引用非法内存触发 Kernel Panic 重启！
  4. 即使完全不操作，每秒 4 次的分配与释放很快导致 FreeRTOS 堆内存碎片化，最终内存耗尽崩溃！

### 根因 2：激进的 2 分钟调暗与 15 分钟 0% 息屏，且无副板 PIR 导致“死机不响应” (`screen_display.c`)
- **致命缺陷**：
  1.1.42 引入了免触调光逻辑，本意是配合副板 PIR 传感器，但在实机未插物理副板（或处于桌面随身屏常亮场景）时：
  - 静置 120 秒（2 分钟）自动调暗到 20%；
  - 静置 900 秒（15 分钟）自动设置背光为 0%（全黑关屏）！
- **后果**：
  1. 随身屏完全黑屏后，用户从视觉上以为设备关机或死机；
  2. 旋转、翻转、晃动设备均不会唤醒屏幕；
  3. 当用户尝试盲摸触屏时，唤醒代码未标记 `consumed`，触控事件直接穿透触发屏幕底层控件，造成误触甚至切页；
  4. 唤醒代码硬编码恢复为 `80` 亮度，直接覆盖了用户在控制中心手动设置的自定义亮度。

### 根因 3：重力旋转与切页转场并发竞态冲突 (`screen_display.c`)
- **缺陷**：
  在 `rotate_display` 中未检查 `a->page != a->next_page`。当用户左右滑动切页松手时，`poll_touch` 已将 `a->next_page` 设为目标页，但紧接着 `rotate_display` 在同一周期内触发了硬件 MADCTL 旋转并调用全屏 `lv_refr_now`，导致转场动画缓冲区与屏幕硬件寄存器方向错乱，造成画面撕裂与冻结。

### 根因 4：对象指针未置空 (`screen_ui.c`)
- 控制中心亮度标签 `a->brightness_label` 在切页 `screen_ui_build` 时未置为 `NULL`，存在潜在悬空指针风险。

## 3. 彻底修复与工程落地

1. **`screen_widget.c` 根治对象销毁与槽位复用**：
   - 引入专用 `a->widget_empty_card` 指针追踪空卡片生命周期；
   - 仅在列表从有任务变为空时创建一次空卡片，后续刷新 0 内存开销；
   - 当有任务注入时，单次安全删除空卡片并复用既有组件（In-place update），彻底杜绝每 250ms 的 `lv_obj_clean` 闪烁与内存碎片；
   - 彻底解决 1 个任务时的误删卡片 Bug，保证触屏点击与滑动百分之百安全。
2. **`screen_display.c` 重塑息屏与桌面常亮策略**：
   - 彻底废除 0% 全黑息屏机制（随身屏作为桌面伙伴常亮不黑屏）；
   - 调暗超时时间由 2 分钟大幅延长至 10 分钟，且调暗底线为柔和的 40%（依然清晰可读）；
   - 唤醒时准确还原用户在控制中心设定的 `a->current_brightness`，不再粗暴写死 80；
   - 处于调暗状态下的首次触屏仅用于唤醒并吞掉（`consumed = true`），彻底杜绝盲按误触；
   - `rotate_display` 增加 `a->page != a->next_page` 保护，杜绝转场与旋转竞态。
3. **`screen_sensors.c` 引入拿起与旋转体感即刻唤醒**：
   - 监测姿态朝向变化（`s->orientation.down_face != prev_face`），当用户拿起、旋转、倾斜设备时，即刻触发 `screen_activity_kick(a)` 恢复全屏亮度。
4. **`screen_ui.c` 指针清空收拢**：
   - `screen_ui_build` 统一将 `a->brightness_label = NULL;` 与 `a->widget_empty_card = NULL;` 彻底清空。
5. **版本升级**：
   - 全局升级为 **1.1.44**。
