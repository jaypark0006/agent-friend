# LAN Screen — confirmed product baseline

2026-10-03 (Asia/Shanghai). Independent ESP32-S31 firmware; user confirmed implementation.

- Native 480×480 live images generated by the user's own LAN programs. Target 30 displayed FPS, not yet measured.
- Binary baseline JPEG over persistent WebSocket; REST single-frame fallback. Bounded newest-frame-wins buffering, no playback backlog.
- LVGL settings: top-edge downward swipe opens settings. Wi-Fi icon opens scan list and on-device English password keyboard. Status icon exposes IP and API addresses. Bottom-edge upward swipe returns home from every page, including keyboard. Secondary information uses horizontal paging; Wi-Fi list scrolls vertically.
- Settings do not interrupt reception; return to latest image. Touch gestures begin at screen edge to avoid list/keyboard conflicts.
- REST sensor snapshot and continuous WS telemetry. IMU g / degrees per second, magnetometers microtesla, battery millivolts / milliamps / Celsius. Failed sensors report unavailable, not fabricated zeroes.
- Preserve retained Vibe Mode and ESP-Iris. Do not erase existing firmware/settings during development.

Implementation: `vendor/esp-mosaico-vibe/projects/lan_screen` initialized using official CLI template. Use LVGL by user choice; replace template GSP resources, preserve recovery layout.

Pinned Vibe IDF: 7b9cc1ac79f865983f59bb8ff3ff43eb74ff1dbe. BSP is Vibe's pinned submodule. All performance remains an estimate until hardware validation.

Display budget: BSP 40 MHz × 4 bits = ideal 20 MB/s. RGB565 frame 480×480×2 = 460800 bytes → ideal 23.04 ms. Actual overhead and network contention require measurement; 60 full-screen FPS is outside this default bus budget. S31 hardware JPEG supports baseline JPEG; reference: official BSP `examples/usb_extend_screen` and ESP-IDF S31 JPEG documentation. EAF is an available prerecorded animation container, not proof of the installed factory app's codec.
