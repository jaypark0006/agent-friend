# Claude 控制台设计咨询

2026-10-04，按用户要求通过本机 Claude CLI 咨询设计。只提供现有静态 HTML/CSS，请求工具禁用，未让该会话修改代码或执行测试。

请求模型参数：`claude-opus-5-5`。CLI 返回的该项 canonicalModel 为 `claude-opus-5`；这里保留实际返回标记，不另行声称已核验后台模型身份。

采纳：缩小导航/卡片/预览尺寸；图片文字同页并列；图片用 WS ACK 直接确认接收；传感器一个开关连接即接收；HTTP 示例预填、方法/路径/目标/执行同行，高级字段默认折叠。

结合用户后续要求：查看设备和设备控制合成设备页，自动切换放同页快速设置区；推送仍有独立入口，取消独立首页和网页设置页；摄像头色块为独立新功能页。

以下是咨询返回的原文，仅作为设计参考；与用户要求冲突的建议不采用。

以下建议全部基于现有静态 HTML/CSS + ES Module 可实现，不引入任何框架。

## 一、信息架构：5 页并为 3 页

- 删除首页 hero 与两张入口卡——"查看/发送两个入口"正是操作绕的根源，浏览器打开直接进控制台。
- 侧栏只留三项：**控制台、设备状态、HTTP 调试**。设备设置并入设备状态页顶部一条（自动切换开关）。

## 二、控制台：单页双栏，收发并列

- **左栏（约 42%）**：设备当前画面卡——实时预览开关（默认关，带宽原因保留）、获取画面上方一行、切页 segmented、未读数和 FPS 做成底部一行小字。
- **右栏（约 58%）**：图片卡与文字卡**同页同排并列**（≥900px 两列，窄屏上下堆叠），不做 type-picker、不做 tab。
  - 图片卡：拖放区即预览（选图后显示 240px 缩略图 + 文件名/转换后 KB），布局 select 与发送按钮同行。
  - 文字卡：textarea（Ctrl+Enter 发送）+ 右侧 240px 迷你屏示意，字号/对齐/时间三件控件并排一行，不再单独折叠。
- 发送状态只占一行内联文案：发送中… → 绿「设备**已接收** #id」→ 红错误信息。**绝不写"已显示/已读"**，ACK 仅代表接收。

## 三、图片发送：用 /ws/frames 的 ACK，不做任何轮询

- 发送二进制 JPEG 后等待 JSON 响应：`{accepted:id}` → 成功行；`{error:message}` → 错误行；3–5 秒超时提示「未收到确认」。
- 删除「接收/显示/替换」计数对照与显示性能折叠，这些数字对用户无意义。

## 四、传感器：一个开关即全部

- 设备状态页传感器区顶部放**「实时传感器」开关**：打开立即连 `ws://IP:81/ws/sensors`，一次订阅更新所有格子（加速度/按键/麦克风/摄像头/子板），badge 显示「实时/已断开」；关闭即断连、保留最后值。
- 删除「刷新状态」按钮、原始 JSON+复制按钮、各传感器的两枚开/关双钮（若需控制摄像头/麦克风，留一个 toggle 即可）。
- 静态信息（Wi-Fi、IP、电量）进页拉一次 /api/status。若固件能把未读数并入 WS 事件流，连这些也移入实时流。

## 五、HTTP 调试瘦身

- 左侧保留请求集合（查看/发送分组、预填样例、每项自带默认 Mock）；右侧一行：method + path + 目标 + 执行。
- 参数区全部默认折叠：Headers、Body、Mock（Mock 做成开关，模板仅在展开时可见）；响应 Headers 始终折叠。
- 删「更多入口」details、空白引导页（默认选中第一个示例）、Swagger 式文档页；接口清单 JSON 链接降级为页脚一行小字。

## 六、值得删的冗余清单

首页 hero/入口卡；独立推送页的 type-picker；文字独立排版预览卡；传感器原始 JSON/复制；显示性能折叠；状态刷新按钮；HTTP 空白引导页；下载响应/WAV/原始帧链接降级为一排小字文本。

## 七、密度与视觉

- topbar 74→48px；卡片 padding 24→16、标题下距 22→14、圆角 12px；正文 13px。留白靠卡片间距（16px）而非内边距。
- 语义色固定：蓝=操作、绿=已接收/在线、琥珀=等待、红=失败；按钮只保留主操作一个，其余降为 text-button。
- 全部提示文案压缩为一行，删除占两行的说明句（如「只切换设备页面，已接收的内容会保留」可并入次行小字）。
