# 滑动过渡

2026-10-04：用户反馈左右、上下划没有动画。原因是主页面重建时直接清空旧LVGL页面，图片历史则直接替换LCD全屏像素。1.1.9源码加入方向一致的切换过渡，包含上一版消息到达配置。未编译、运行、刷入或自测，设备仍1.1.7。

## 界面行为

- 主图片/文字页左右切换、状态四页左右切换：沿手势方向滑入滑出。
- 图片历史向下查看更旧、向上查看更新：纵向滑动；到历史边界不播放无效切换。
- 顶边下拉设置、设置底边上滑返回：纵向滑动。设置内按钮导航也有过渡。
- 自动切到文字页和显式API切页使用同一套过渡。文字内容上下保持LVGL原生连续滚动/惯性，不变成逐条跳换。

过渡约230ms，缓入缓出，在已有手势阈值达到后开始；不是整个拖动期间逐像素跟随手指。合成帧按33,333µs调度，实际速度需用户后续体验，不是30FPS验收。

## 显示实现

显示任务先等待旧LCD传输完成，保存当前实际画面；在屏外构建目标页，避免动画开始前闪出新页面。GUI分块只写镜像，图片由现有硬件JPEG解码产生目标。新旧页面各一份RGB565快照与一份合成帧，总计约1.32MiB PSRAM，由`screen_transition`对象持有，初始化失败释放缓冲。

合成采用整行或连续片段复制，无逐像素缩放。LCD发送前等待上一帧DMA完成，再复用合成帧。分配使用现有JPEG输出缓冲分配器匹配S31外部内存与缓存对齐，不能同时要求PSRAM和仅内部内存具备的MALLOC_CAP_DMA。

过渡不阻塞网络任务，新推送继续进入现有有界历史/最新帧队列；显示任务期间读取触摸但不再次切页，暂缓重力旋转，完成后处理已接收的新内容和导航请求。消息阅读停留计时在目标实际可见后开始。若目标含新接收JPEG，只在过渡最终帧LCD完成时计一次displayed。

截图仍从已完成LCD的画面捕获，包括过渡中间帧；不会捕获屏外准备的新页。`/api/status.transitioning`在目标最终LCD传输完成后清除，显示完成内容版本号不提前推进。原GUI/JPEG帧率计数不作为动画性能验收。
