# 姿态 API 开发与标定

用户需求（2026-10-03）：程序查询机器哪一边朝下，以此决定发送画面的方向。保留已有传感器 REST 和 WebSocket，新增明确的姿态结果。每个独立改动提交 Git。

## 坐标依据

固定 BSP 的 `onboard/sensors.c` 直接返回 BMI270 XYZ 加速度 g，未做屏幕坐标转换。不能把 IMU X/Y 自动假定为屏幕左右/上下。

用户已明确确认目前屏幕朝上平放。此前快照 accel_g=[-0.0575,0.0247,1.0074]；再次采样附在本文件下方。由此确认 IMU +Z 对应屏幕朝外方向；X/Y 对应待 Type-C 朝下的竖直姿态采样确认。

计划屏幕坐标：+X 朝右、+Y 朝上（橙色 AI 键所在边）、+Z 朝屏幕外。朝下向量为静止/缓慢移动时加速度的负方向。旋转角定义为从屏幕正面观看，将原始图像顺时针旋转的角度。屏幕朝上/朝下平放时，重力无法决定画面平面内旋转，应返回 null 并保留客户端上次角度。

实现将包含低通、朝向切换滞回、短时稳定确认，并对传感器失效、自由落体、强加速度和大角速度返回未知/不建议旋转。重力姿态不提供罗盘方向；磁场数据不是此功能的依据。

## X/Y 核对结果

用户再次确认竖直、Type-C 朝下，并轻轻倾斜后放稳。后续数据 +Y 为主（约 0.93–0.96g），+Z 为较小倾斜分量；刚才 +Z 快照采于实体姿态改变前。重新采样中位值：[0.0677490234375, 0.9212646484375, 0.3602294921875].

确认屏幕坐标与 IMU XYZ 一致：+Y 朝顶部，+Z 朝屏幕外，右手坐标的 +X 朝右。静止时加速度与朝下方向相反。Type-C 朝下时应返回 down_face=bottom，rotation_cw_deg=0；左侧朝下则 rotation_cw_deg=90，顶部朝下为180，右侧朝下为270。屏幕朝上时朝下的是 back，屏幕朝下时朝下的是 screen，均不由重力决定画面旋转角。
