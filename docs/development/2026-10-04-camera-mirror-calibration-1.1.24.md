## 变换修正

上一版只包含270°顺时针安装校正及按纯旋转计算的屏幕补偿，未纳入左右校正。现将原始传感器到屏幕原生坐标的安装映射写为 `Mx * R(270)`（先旋转，再水平翻转）。逆屏幕变换应作用于校正后的坐标：

`R(-display) * Mx * R(270) = Mx * R(270 + display)`。

反射与旋转不能交换次序且保持相同角度符号。显示复制、转向重绘、HTTP处理帧预览共享source_pixel坐标查找：先将目标X反向，再查找相应旋转的源像素；逻辑帧顺时针角改为 `(270 + display_rotation_cw_deg) % 360`，随后水平翻转。

| 实际LCD角度 | 先顺时针旋转 | 随后水平翻转 |
| --- | --- | --- |
| 0° | 270° | 是 |
| 90° | 0° | 是 |
| 180° | 90° | 是 |
| 270° | 180° | 是 |

相对1.1.23，0°与180°保持上下方向并校正左右；90°与270°调整180°并校正左右，针对用户本轮描述的三种表现。此表描述源代码映射，不作为实机效果验收。

摄像头页LCD/界面/触摸仍随重力；只变换摄像头像素，提示标记在变换后叠加。2×2四点RGB平均、中心裁切/缩放、自动开关与原始采集帧API保留；无新图像缓冲、分区或恢复固件契约变化。orientation/status/传感器WS增加camera_frame_mirror_x=true，camera.render增加mirror_x=true，HTTP处理帧响应头增加X-Frame-Mirror-X:true；原有旋转字段是水平翻转之前的角度。
